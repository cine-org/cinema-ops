# Setup VPS

> Base OS setup for a fresh VPS, done once before installing k3s. Goal: a secure, minimal, repeatable baseline — nothing app-specific yet.

## 1. First login

```bash
ssh root@VPS_IP
```

## 2. Update the system

```bash
sudo apt update && sudo apt upgrade -y
```

- `update`: refresh the package index.
- `upgrade`: install available updates.

Quick health check:

```bash
uname -r
uptime
df -h
free -m
```

## 3. Create the `ops` user

Never run services as `root`.

```bash
sudo adduser ops
sudo usermod -aG sudo ops
```

Generate a strong password when prompted:

```bash
openssl rand -hex 24
```

## 4. Generate an SSH key (local machine)

```bash
ssh-keygen -t ed25519 -C "ops-key"
```

- Private key (`id_ed25519`) never leaves your machine.
- Only the public key (`id_ed25519.pub`) goes to the VPS.

Optional local `~/.ssh/config` entry:

```
Host cinema-staging
    HostName VPS_IP
    User ops
    IdentityFile ~/.ssh/id_ed25519
```

## 5. Add the public key to the VPS

```bash
mkdir -p /home/ops/.ssh
nano /home/ops/.ssh/authorized_keys   # paste the .pub content
chown -R ops:ops /home/ops/.ssh
chmod 700 /home/ops/.ssh
chmod 600 /home/ops/.ssh/authorized_keys
```

Wrong permissions silently break key login.

## 6. Test key-based login

```bash
ssh ops@VPS_IP   # or: ssh cinema-staging
```

## 7. Harden SSH

Edit `/etc/ssh/sshd_config`:

```
PermitRootLogin no
PasswordAuthentication no
PubkeyAuthentication yes
```

```bash
sudo systemctl restart ssh
```

⚠️ Confirm key-based login works (step 6) **before** disabling password auth — otherwise you can get locked out.

## 8. Firewall (ufw)

```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing

sudo ufw allow 22    # SSH
sudo ufw allow 80    # HTTP (Traefik ingress)
sudo ufw allow 443   # HTTPS (Traefik ingress)
# sudo ufw allow 6443 # k3s API server — only if kubectl is needed from outside the VPS

sudo ufw enable
sudo ufw status
```

If the provider also has a cloud-level firewall, mirror the same rules there (default deny, allow 22/80/443).

## 9. Fail2ban (brute-force protection)

```bash
sudo apt install fail2ban -y
sudo systemctl enable --now fail2ban
sudo fail2ban-client status
```

## 10. Base tools

```bash
sudo apt install -y git curl wget unzip htop
```

No longer installed here, since the app now runs on k3s instead of Docker Compose on the host:

- ~~`nginx`~~ → replaced by Traefik, bundled with k3s.
- ~~`docker` / `docker-compose-plugin`~~ → replaced by k3s's built-in container runtime (containerd).

## 11. Swap RAM

1. Create

```bash
sudo fallocate -l 2G /swapfile
```

Fallback bằng dd

```bash
sudo dd if=/dev/zero of=/swapfile bs=1M count=2048
```

```bash
sudo chmod 600 /swapfile                # Permission
sudo mkswap /swapfile                   # Create swap area
sudo swapon /swapfile                   # Enable
sudo sysctl vm.vfs_cache_pressure=50    # Cache
```

2.Auto mount

> reboot → mất swap

`/etc/fstab` = file mount khi boot

```bash
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

## Troubleshooting: manual git access on the VPS

Only needed if you ever `git clone`/`pull` by hand on the VPS for debugging — not required for Argo CD, which uses its own separate Git credential configured inside Argo CD itself.

No SSH key needed: use a PAT over HTTPS instead.

```bash
git clone https://<PAT>@github.com/<org>/<repo>.git
```

Note: `GHCR_PULL_PAT` is scoped for `read:packages` (GHCR pulls) — it may not have `repo`/`Contents: read` scope for cloning a private repo. Use a separate PAT for that if needed.

## Troubleshooting: DNS not resolving GitHub

```bash
sudo nano /etc/resolv.conf
```

```
nameserver 1.1.1.1   # Cloudflare
nameserver 1.0.0.1
nameserver 8.8.8.8    # Google (fallback)
nameserver 8.8.4.4
```
