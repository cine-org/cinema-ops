# 4. Secrets: External Secrets Operator + Google Secret Manager

Mục tiêu: password thật (Postgres, sau này Redis/`cinema`) không bao giờ chạm Git dưới bất kỳ hình thức nào (kể cả mã hoá) — nằm hẳn ở Google Secret Manager (GSM), cluster chỉ đồng bộ về khi cần.

Chọn GSM vì có tier **Always Free** thật sự lặp lại hàng tháng (6 secret version + 10.000 lượt truy cập/tháng, không phải credit dùng thử) — đủ dùng cho quy mô dự án này.

## Việc chỉ làm 1 lần, thủ công, ngoài Git

### 1. GCP: tạo Service Account + key

```text
GCP Console → IAM & Admin → Service Accounts → Create
  Role: Secret Manager Secret Accessor
→ Keys → Add key → JSON → tải về máy
```

### 2. GCP: tạo secret thật trong Secret Manager

> GCP Console → Security → Secret Manager → Create secret: platform-postgres

```json
{
  "username": "cinema",
  "password": "<openssl rand -hex 24>"
}
```

Prefix `platform-` phân biệt hạ tầng/app (sau này `cinema-xxx`). Value là JSON vì CNPG (`bootstrap.initdb.secret`) cần Secret K8s có đủ 2 key `username`+`password`.

### 3. VPS: đưa JSON key vào cluster (Kubernetes Secret, không qua Git)

Cú pháp tạo secrets

```bash
kubectl create secret generic <SECRET_NAME> \
  --from-literal=<KEY>=<VALUE> \
  -n <NAMESPACE>
```

```bash
export KUBECONFIG=$HOME/.kube/config
kubectl create secret generic gcpsm-credentials \
  --from-file=secret-access-credentials=<path-tới-file.json> \
  -n platform
```

Xoá file JSON key khỏi máy sau khi chạy xong lệnh trên (không cần giữ lại, K8s Secret trong cluster đã đủ).

## Phần tự động qua Git (đã có sẵn trong repo)

`applications/platform/external-secrets.yaml` — cài operator:

```yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: external-secrets
  namespace: argocd
spec:
  project: default

  source:
    repoURL: https://charts.external-secrets.io
    chart: external-secrets
    targetRevision: 2.10.0
    helm:
      values: |
        resources:
          requests:
            cpu: 50m
            memory: 64Mi
          limits:
            memory: 256Mi

  destination:
    server: https://kubernetes.default.svc
    namespace: platform

  syncPolicy:
    automated:
      enabled: true
      prune: true
      selfHeal: true
    syncOptions:
      - CreateNamespace=true
      - ServerSideApply=true
    retry:
      limit: 5
      backoff:
        duration: 5s
        factor: 2
        maxDuration: 3m
```

CRD của external-secrets rất lớn — thiếu `ServerSideApply=true` là sync fail vì vượt trần annotation 262144 byte.

`resources/gcp-secret-store.yaml` — trỏ tới GSM, xác thực bằng Secret `gcpsm-credentials` tạo ở bước 3 (chỉ tham chiếu tên, không chứa giá trị):

```yaml
apiVersion: external-secrets.io/v1
kind: ClusterSecretStore
metadata:
  name: gcp-secret-manager
spec:
  provider:
    gcpsm:
      projectID: "<GCP project ID>"
      auth:
        secretRef:
          secretAccessKeySecretRef:
            name: gcpsm-credentials
            key: secret-access-credentials
            namespace: platform
```

`ClusterSecretStore` là cluster-scoped nên mọi namespace đều dùng chung được (bản namespace-scoped là `SecretStore`).

## Verify

```bash
kubectl get clustersecretstore gcp-secret-manager -o yaml
```

Trạng thái `Valid` nghĩa là ESO xác thực GSM thành công. Nếu `Invalid`, thường do bước 1-3 chưa đúng (sai role, sai tên Secret, hoặc chưa sửa `projectID`).
