# 5. Postgres: CloudNativePG (CNPG)

Mục tiêu: 1 instance Postgres trong namespace `platform`, database `cinema`, credential kéo từ Secret Manager qua External Secrets — không tạo secret tay, không viết StatefulSet tay.

CNPG là operator: cài 1 lần, có thêm CRD `Cluster`. Khai báo `Cluster` ngắn, operator tự dựng StatefulSet + PVC + Service + failover phía sau.

## Cách wiring vào Argo CD

Doc này thêm 3 file (đánh dấu `+`):

```text
k8s/environments/staging/
├── applications/
│   ├── platform-resources.yaml
│   └── platform/
│       ├── external-secrets.yaml
│     + └── cnpg-operator.yaml
└── resources/
    ├── namespaces.yaml
    ├── gcp-secret-store.yaml
  + ├── postgres-external-secret.yaml
  + └── postgres-cluster.yaml
```

`root-staging` quét `applications/` → dựng Application `cnpg-operator` (Helm chart ngoài, kèm CRD nên đứng riêng). `platform-resources` trỏ vào `resources/` nên 2 file postgres bỏ vào đó là tự được apply — CR thường, không cần Application riêng.

`Cluster` cần CRD từ operator mà 2 Application sync song song → lần đầu `platform-resources` có thể fail 1 nhịp rồi tự chạy lại nhờ `retry`.

## Files

### 1. `applications/platform/cnpg-operator.yaml`

```yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: cnpg-operator
  namespace: argocd
spec:
  project: default

  source:
    repoURL: https://cloudnative-pg.github.io/charts
    chart: cloudnative-pg
    targetRevision: 0.29.0

  destination:
    server: https://kubernetes.default.svc
    namespace: cnpg-system

  syncPolicy:
    automated:
      enabled: true
      prune: true
      selfHeal: true
    syncOptions:
      - CreateNamespace=true
      - ServerSideApply=true
    retry:
      limit: 5
      backoff:
        duration: 5s
        factor: 2
        maxDuration: 3m
```

CRD của CNPG lớn nên bắt buộc `ServerSideApply=true`. Namespace `cnpg-system` (mặc định CNPG) — operator tách khỏi `platform` nơi chứa database.

### 2. `resources/postgres-external-secret.yaml`

```yaml
apiVersion: external-secrets.io/v1
kind: ExternalSecret
metadata:
  name: platform-postgres
  namespace: platform
spec:
  refreshInterval: 1h
  secretStoreRef:
    name: gcp-secret-manager
    kind: ClusterSecretStore
  target:
    name: platform-postgres
  data:
    - secretKey: username
      remoteRef:
        key: platform-postgres
        property: username
    - secretKey: password
      remoteRef:
        key: platform-postgres
        property: password
```

`ExternalSecret` là công thức, không phải secret: Git chứa công thức, ESO sinh Secret K8s thật trong cluster.

```text
GSM: platform-postgres = {"username":"cinema","password":"a1b2..."}
  ↓ ESO đọc qua ClusterSecretStore gcp-secret-manager
K8s Secret platform-postgres (ns platform): username=cinema, password=a1b2...
  ↓ CNPG đọc qua bootstrap.initdb.secret
Postgres: role "cinema" với password đó
```

Mỗi mục `data` là 1 key của Secret K8s:

| Field | Nghĩa |
| --- | --- |
| `secretKey` | tên key trong Secret K8s — `username`/`password` là 2 tên CNPG bắt buộc |
| `remoteRef.key` | tên secret bên GSM |
| `remoteRef.property` | field bên trong JSON; value là chuỗi trần thì bỏ đi |

- Có cách viết tắt `dataFrom.extract` (đổ hết key trong JSON vào Secret), cố ý không dùng — liệt kê ra thì đọc file biết ngay Secret có gì.
- `secretStoreRef.kind` phải ghi rõ `ClusterSecretStore`, bỏ trống ESO hiểu là `SecretStore` namespace-scoped → không tìm thấy.
- `target.name` là tên Secret sinh ra, bỏ trống thì lấy `metadata.name`. 3 chỗ trùng tên `platform-postgres` là 3 thứ khác nhau: secret GSM / ExternalSecret / Secret K8s.
- `refreshInterval` là chu kỳ đối chiếu lại GSM. Đổi password bên GSM thì Secret tự cập nhật, Postgres thì không (`initdb` chạy 1 lần).
- Secret sinh ra thuộc sở hữu `ExternalSecret` (`creationPolicy: Owner` mặc định) — xoá công thức là Secret mất theo. Argo CD chỉ quản `ExternalSecret`.

### 3. `resources/postgres-cluster.yaml`

```yaml
apiVersion: postgresql.cnpg.io/v1
kind: Cluster
metadata:
  name: postgres
  namespace: platform
spec:
  instances: 1

  bootstrap:
    initdb:
      database: cinema
      owner: cinema
      secret:
        name: platform-postgres

  managed:
    roles:
      - name: cinema_rw
        ensure: present
        login: true
        inherit: true
        connectionLimit: -1
        passwordSecret:
          name: platform-postgres-rw
        inRoles:
          - pg_read_all_data
          - pg_write_all_data

      - name: cinema_ro
        ensure: present
        login: true
        inherit: true
        connectionLimit: -1
        passwordSecret:
          name: platform-postgres-ro
        inRoles:
          - pg_read_all_data

  storage:
    size: 5Gi

  resources:
    requests:
      cpu: 100m
      memory: 256Mi
    limits:
      memory: 512Mi
```

- `bootstrap.initdb` chỉ chạy 1 lần lúc cluster còn rỗng; sửa về sau không tạo lại database.
- `inherit: true` và `connectionLimit: -1` là giá trị mặc định nhưng vẫn phải khai: webhook CNPG điền chúng vào từng phần tử `managed.roles`, thiếu trong Git thì Argo CD OutOfSync vĩnh viễn.
- Không khai `storageClass` → default k3s (`local-path`, đĩa VPS). PVC không co lại được nên 5Gi là sàn.
- Không đặt `limits.cpu`: CPU quá hạn chỉ bị throttle, RAM mới cần chặn cứng để khỏi OOM cả node.

`managed.roles` tách quyền: `cinema` (owner, do `initdb` tạo) giữ DDL cho migration, `cinema_rw` chỉ đọc/ghi dữ liệu, `cinema_ro` chỉ đọc. Ba điểm đáng nhớ:

- `pg_read_all_data`/`pg_write_all_data` là predefined role có sẵn của Postgres (từ PG 14). Quyền áp **động** lúc truy cập nên bảng do migration tạo sau này tự được phủ — đây là lý do không cần Job chạy `GRANT` kèm `ALTER DEFAULT PRIVILEGES`.
- `passwordSecret` trỏ tới Secret có key `username` **đúng bằng tên role**, type `kubernetes.io/basic-auth`. Chú ý hai hệ tên nằm cạnh nhau: tên Secret/GSM dùng gạch ngang (`platform-postgres-rw`, K8s không cho gạch dưới), tên role dùng gạch dưới (`cinema_rw`). Ghi `cinema-rw` vào `username` là CNPG từ chối tạo role, nhưng `Cluster` vẫn `Healthy` — lý do chỉ hiện ở `kubectl get cluster postgres -n platform -o jsonpath='{.status.managedRolesStatus}'`.
- `pg_write_all_data` **không** gồm `TRUNCATE` (là quyền riêng). `cinema_rw` xoá sạch bảng bằng `DELETE FROM` được, bằng `TRUNCATE` thì bị chặn — script seed/test dùng `TRUNCATE` phải chạy bằng `cinema`.
- Khác `initdb`, role ở đây có đổi password theo Secret — CNPG lưu `resourceVersion` của Secret trong `status.managedRolesStatus.passwordStatus`. Nhưng nó chỉ áp vào **lần reconcile kế tiếp**, mà Argo CD apply không đổi gì thì không sinh event để reconcile. Muốn có ngay thì ép: `kubectl rollout restart deployment cnpg-operator-cloudnative-pg -n cnpg-system`.

2 Secret đó do 2 `ExternalSecret` cùng nằm trong `postgres-external-secret.yaml` sinh ra, cấu trúc y hệt cái của owner, chỉ thêm `target.template.type: kubernetes.io/basic-auth`.

## Verify

```bash
kubectl get pods -n cnpg-system
kubectl get externalsecret -n platform
kubectl get cluster -n platform
kubectl get pods -n platform -l cnpg.io/cluster=postgres
kubectl exec -it -n platform postgres-1 -- psql -U postgres -d cinema -c '\du'
```

Xong khi `externalsecret` = `SecretSynced`, `cluster` cột `STATUS` = `Cluster in healthy state`, pod `postgres-1` Running, `\du` thấy đủ `cinema`, `cinema_rw`, `cinema_ro`.

Phân quyền phải thử bằng câu lệnh thật, nhìn `\du` không đủ:

```bash
kubectl exec -n platform postgres-1 -c postgres -- \
  psql -U postgres -d cinema -c 'create table if not exists t_check(id serial primary key, note text)'

PW=$(kubectl get secret platform-postgres-rw -n platform -o jsonpath='{.data.password}' | base64 -d)
kubectl exec -n platform postgres-1 -c postgres -- env PGPASSWORD="$PW" \
  psql -h 127.0.0.1 -U cinema_rw -d cinema \
  -c "insert into t_check(note) values ('ok') returning id" \
  -c "create table t_deny(x int)"
```

`insert` phải chạy được (chứng minh có quyền trên sequence của `serial` — chỗ hay hụt), `create table` phải báo `permission denied`. Làm tương tự với `cinema_ro`: `select` chạy, `insert` bị chặn. Dọn: `drop table t_check`.

Bắt buộc có `-h 127.0.0.1` — thiếu nó psql nối qua Unix socket và xác thực bằng peer, không kiểm tra password nên thử nghiệm vô nghĩa.

Nếu role không xuất hiện, xem lý do ở:

```bash
kubectl get cluster postgres -n platform -o jsonpath='{.status.managedRolesStatus}'; echo
```

`cannotReconcile` là CNPG từ chối tạo role và ghi lý do; `Cluster` vẫn `Healthy` nên `kubectl get cluster` không hé lộ gì. Sửa xong nguyên nhân mà status vẫn kẹt thì restart operator để ép reconcile (không ảnh hưởng Postgres đang chạy).

Cuối cùng, kiểm tra dữ liệu bền qua restart — ghi 1 dòng, `kubectl delete pod postgres-1 -n platform`, chờ pod lên rồi đọc lại. PVC cũ phải được gắn lại (so `kubectl get pvc -n platform` trước/sau) và dòng đó còn nguyên.

## Kết nối từ app

| Service (ns `platform`) | Dùng cho                            |
| ----------------------- | ----------------------------------- |
| `postgres-rw`           | đọc + ghi, primary — mặc định       |
| `postgres-ro`           | chỉ đọc, chỉ replica (hiện chưa có) |
| `postgres-r`            | chỉ đọc, mọi instance               |

Credential là Secret `platform-postgres`. Secret không dùng chéo namespace nên app ở ns `cinema` cần `ExternalSecret` riêng trỏ cùng key GSM.

## Để dành sau

- `instances: 1`, chưa HA — tăng số này là operator tự lo replication. Đo trên staging: mỗi replica thêm ~55–75Mi RAM khi rảnh và 1 PVC bằng `storage.size`.
- Chưa có `Pooler` (PgBouncer): cần khi connection từ app tăng.
- Chưa có backup (`spec.backup` → object storage): làm trước khi có dữ liệu thật.
- `imageName` trống → Postgres version mặc định của operator.
