# 7. cert-manager

Mục tiêu: cài cert-manager để cluster tự cấp và tự gia hạn chứng chỉ TLS. Chỉ cài bộ máy, **chưa** tạo `ClusterIssuer` nào.

Dùng ở đâu:

- Sau này: webhook của operator RabbitMQ xin chứng chỉ qua cert-manager.
- Sau này: chứng chỉ HTTPS Let's Encrypt cho Ingress.

## Khái niệm

**Chứng chỉ** = khoá riêng (giữ bí mật) + giấy xác nhận "khoá này thuộc về tên X", có chữ ký của một bên ký. Bên ký có thể là:

- **CA nội bộ / tự ký**: chỉ những thành phần trong cluster được cấu hình tin CA đó mới tin. Đủ cho webhook.
- **Let's Encrypt**: mọi trình duyệt đều tin. Dùng cho website.

Chứng chỉ có hạn dùng. cert-manager tự gia hạn trước khi hết hạn — lý do chính để dùng nó thay vì tạo tay bằng `openssl`.

cert-manager làm việc qua các CRD:

| Kind | Nghĩa |
| --- | --- |
| `Issuer` | "Ai ký?", chỉ dùng trong namespace của nó |
| `ClusterIssuer` | Như `Issuer` nhưng dùng cho mọi namespace |
| `Certificate` | "Cần chứng chỉ cho tên X, do Issuer Y ký, lưu vào Secret Z" |

Kết quả là 1 Secret kiểu `kubernetes.io/tls` chứa `tls.crt`, `tls.key` (và `ca.crt`). Pod mount Secret đó để dùng.

Chart cài 3 pod:

```text
cert-manager             controller: thấy Certificate → nhờ Issuer ký → ghi Secret, tự gia hạn
cert-manager-webhook     kiểm tra YAML Certificate/Issuer trước khi K8s lưu
cert-manager-cainjector  chép CA vào cấu hình webhook của operator khác (annotation
                         cert-manager.io/inject-ca-from) để API server tin webhook đó
```

**Webhook** là gì: khi `apply` một CR, API server gọi HTTPS sang operator hỏi "YAML này hợp lệ không?" trước khi lưu. Vì là HTTPS nên operator phải có chứng chỉ. CNPG và redis-operator tự sinh chứng chỉ bên trong; 2 operator RabbitMQ thì giao việc đó cho cert-manager.

## Cách wiring vào Argo CD

Doc này thêm (đánh dấu `+`):

```text
k8s/environments/staging/
└── applications/platform/
      + └── cert-manager.yaml
```

Helm chart → Application giống CNPG/redis-operator.

## File: `applications/platform/cert-manager.yaml`

```yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: cert-manager
  namespace: argocd
spec:
  project: default

  source:
    repoURL: https://charts.jetstack.io
    chart: cert-manager
    targetRevision: v1.21.2
    helm:
      values: |
        crds:
          enabled: true
        resources:
          requests:
            cpu: 20m
            memory: 64Mi
          limits:
            memory: 256Mi
        webhook:
          resources:
            requests:
              cpu: 10m
              memory: 32Mi
            limits:
              memory: 128Mi
        cainjector:
          resources:
            requests:
              cpu: 10m
              memory: 64Mi
            limits:
              memory: 256Mi

  destination:
    server: https://kubernetes.default.svc
    namespace: cert-manager

  syncPolicy:
    automated:
      enabled: true
      prune: true
      selfHeal: true
    syncOptions:
      - CreateNamespace=true
      - ServerSideApply=true
    retry:
      limit: 5
      backoff:
        duration: 5s
        factor: 2
        maxDuration: 3m
```

- **`crds.enabled: true` là bắt buộc**: chart mặc định **không** cài CRD. Thiếu dòng này thì K8s không biết `Certificate` là gì.
- `crds.keep` mặc định `true`: xoá Application thì CRD (và mọi `Certificate`) vẫn còn, tránh mất chứng chỉ vì lỡ tay.
- `resources` khai cho cả 3 pod, tổng request khoảng 160Mi; lúc chạy thực tế ít hơn.
- `ServerSideApply` vì CRD lớn; `retry` như các Application khác.

## Verify

```bash
kubectl get pods -n cert-manager
kubectl get crd | grep cert-manager.io
```

Xong khi: 3 pod Running, có các CRD `certificates`, `issuers`, `clusterissuers`, `certificaterequests`.

## Thử cấp 1 chứng chỉ (không commit)

Chỉ để thấy cơ chế `Issuer` → `Certificate` → `Secret`. Tạo trong namespace riêng rồi xoá.

```bash
kubectl create namespace cm-test
```

```bash
kubectl apply -f - <<'EOF'
apiVersion: cert-manager.io/v1
kind: Issuer
metadata:
  name: selfsigned
  namespace: cm-test
spec:
  selfSigned: {}
---
apiVersion: cert-manager.io/v1
kind: Certificate
metadata:
  name: demo
  namespace: cm-test
spec:
  secretName: demo-tls
  dnsNames:
    - demo.cm-test.svc
  duration: 24h
  renewBefore: 1h
  issuerRef:
    name: selfsigned
    kind: Issuer
EOF
```

```bash
kubectl get issuer,certificate,secret -n cm-test
```

Mong đợi `issuer` và `certificate` có `READY` = `True`, và Secret `demo-tls` kiểu `kubernetes.io/tls`.

Xem chứng chỉ vừa cấp:

```bash
kubectl get secret demo-tls -n cm-test -o jsonpath='{.data.tls\.crt}' | base64 -d | openssl x509 -noout -subject -issuer -dates -ext subjectAltName
```

Thấy `subjectAltName` là `demo.cm-test.svc`, hạn 24h. `subject` rỗng và `issuer` trùng chính nó — đặc điểm của chứng chỉ tự ký.

Thử self-heal: xoá Secret, cert-manager cấp lại ngay.

```bash
kubectl delete secret demo-tls -n cm-test
```

```bash
kubectl get secret demo-tls -n cm-test
```

Dọn:

```bash
kubectl delete namespace cm-test
```
